# Развёртывание на хостинге

## Требования

- PHP 8.2 или новее;
- PDO MySQL, mbstring, fileinfo, GD, XML, ZIP;
- MySQL 8.x или совместимая MariaDB;
- HTTPS;
- возможность записи PHP в каталог `storage/documents`.

## Готовые файлы релиза

В каталоге `release` создаются два отдельных файла:

- `monitoring-system-code.zip` — код вместе с `vendor`;
- `monitoring-system-production.sql` — снимок рабочей базы.

SQL-файл содержит рабочие данные. Его нельзя загружать в `public_html`: импортируйте его через phpMyAdmin или панель базы данных и храните отдельно.

## Установка

1. Создайте на хостинге пустую БД в кодировке `utf8mb4` и сортировке `utf8mb4_unicode_ci`.
2. Импортируйте `monitoring-system-production.sql`.
3. Распакуйте `monitoring-system-code.zip` в каталог сайта.
4. Скопируйте `config/database.example.php` в `config/database.php` и укажите параметры БД.
5. Скопируйте `config/runtime.example.php` в `config/runtime.php`.
6. В `config/runtime.php` задайте:
   - `base_url`: пустая строка для корня домена или путь вида `/monitoring-system`;
   - `app_url`: полный HTTPS-адрес сайта без завершающего слэша;
   - часовой пояс;
   - путь к закрытому хранилищу документов.
7. Дайте PHP право записи в `storage/documents`. Обычно подходят права 0750 или 0755; точное значение зависит от пользователя PHP на хостинге.
8. Убедитесь, что `.htaccess` загружен и Apache разрешает `AllowOverride`.

Файлы `config/database.php` и `config/runtime.php` содержат настройки сервера и не должны попадать в Git.

## Если импортируется более старая копия БД

После её импорта выполните из корня проекта:

```bash
php database/migrations/20260910_security_hardening.php
php database/migrations/20260911_move_documents.php
php database/migrations/20260911_mariadb_compatibility.php
```

Последняя миграция заменяет специфичную для MySQL 8 сортировку `utf8mb4_0900_ai_ci` на поддерживаемую MariaDB `utf8mb4_unicode_ci`. Перед миграцией всегда создавайте резервную копию. Миграции повторяемы и не создают второго администратора.

## Первый вход

Если текущий администратор использует известный стандартный пароль, после входа система сразу потребует новый пароль длиной не меньше 12 символов. Старый пароль не публикуйте и не оставляйте после запуска.

Если в базе вообще нет администратора, создайте его только из консоли сервера:

```bash
php create_admin.php --create admin "Ответственный сотрудник"
```

Пароль вводится скрыто через стандартный ввод. Через браузер этот файл недоступен.

## Проверка после загрузки

1. Откройте сайт по HTTPS и войдите.
2. Проверьте, что отображаются 24 ноутбука в кабинете 408.
3. Создайте тестовую заявку на один ноутбук.
4. Одобрите её, откройте сформированный акт.
5. Верните ноутбук и убедитесь, что он снова доступен.
6. Проверьте импорт Excel только через предпросмотр, не подтверждая тестовый файл.
7. Проверьте, что URL вида `/config/database.php`, `/database/schema.sql`, `/storage/` и `/audit/` недоступны извне.

После проверки удалите SQL-файл с компьютера, с которого выполнялась загрузка, либо перенесите его в защищённое резервное хранилище.
