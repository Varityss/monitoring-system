# Monitoring System

Система учёта оборудования колледжа на PHP и MySQL: реестр имущества, заявки преподавателей, выдача, возврат, QR/штрихкоды, Excel-импорт, акты и журнал действий.

## Основные правила

- ноутбуки хранятся в кабинете 408;
- остальное оборудование при импорте помещается в кабинет 411;
- статус оборудования меняется только операциями выдачи, возврата и архивации;
- выдача, возврат и обработка заявки выполняются в транзакциях с блокировкой записей;
- преподаватель видит свои заявки и свои акты, административные операции доступны только администратору;
- все изменяющие HTTP-запросы используют POST и CSRF-токен.

## Локальный запуск

1. Требуется PHP 8.2+, MySQL/MariaDB и расширения из `composer.json`.
2. Для новой пустой БД импортируйте `database/schema.sql`.
3. Скопируйте `config/database.example.php` в `config/database.php`.
4. Скопируйте `config/runtime.example.php` в `config/runtime.php`.
5. Установите зависимости: `composer install --no-dev --optimize-autoloader`.
6. Создайте первого администратора командой `php create_admin.php --create admin "ФИО"`.

Для обновления существующей базы используйте PHP-миграции из `database/migrations`. Подробный порядок указан в `DEPLOYMENT.md`.

## Excel

Импорт принимает XLSX/XLS до 10 МБ и до 2000 строк. Формат:

```text
Тип | Модель | Инвентарный № колледжа | Серийный номер | Кабинет | Штрихкод
```

Значение кабинета из таблицы игнорируется согласно текущему правилу размещения. Сначала система проверяет файл и показывает предпросмотр; запись начинается только после отдельного подтверждения администратора.

## Безопасность

Сессия проверяет активность, роль и версию учётной записи при каждом запросе. Деактивация, смена роли и сброс пароля прекращают старые сессии. Вход ограничен по частоте, стандартный пароль требует замены, акты хранятся вне прямой веб-раздачи.

Технический аудит и зафиксированные результаты проверок находятся в `audit`. Этот каталог закрыт правилами веб-сервера и не входит в пакет релиза.
